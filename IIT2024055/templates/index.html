Vulnerable Route (/api/ping/vulnerable)
# Flaw: String concatenation passed to system shell
raw_command = f"ping {PING_COUNT_FLAG} 1 {target}"

output = subprocess.check_output(
    raw_command,
    shell=True,   # Invokes /bin/sh or cmd.exe
    stderr=subprocess.STDOUT,
    text=True,
    timeout=10
)
Mitigated Route (/api/ping/mitigated)
# Defense 1: Strict allow-list regex validation
if not is_valid_target(target):
    return jsonify({"status": "blocked", "error": "Invalid target"}), 400

# Defense 2: Parameterised execution without shell
command_vector = ["ping", PING_COUNT_FLAG, "1", target]
result = subprocess.run(
    command_vector,
    shell=False,  # No shell interpreter; input passed as data
    capture_output=True,
    text=True,
    timeout=10
)

(a) Vulnerable Implementation

Found in app.py inside ping_vulnerable(). The route accepts arbitrary user input from POST body and directly formats it into a command string without sanitization.

(b) Working Exploit

Payload: 127.0.0.1 & whoami

The ampersand (&) acts as a command separator in the shell. The host executes the ping, followed immediately by whoami. Because this is Variant 1 (In-Band), stdout of the chained command is captured and returned directly inside the HTTP response body.

(c) Root Cause

User-supplied input is directly concatenated into a system command string and executed via an operating system shell interpreter (shell=True). The shell parses metacharacters (&, ;, |) as command delimiters rather than literal text, executing arbitrary secondary commands with the privileges of the web process.

(d) Implemented Mitigation

Two layers of defense:

  1. Allow-list validation: Target must match an IPv4/IPv6 address or RFC hostname format; any metacharacters or spaces are rejected with HTTP 400.
  2. Argument vector (shell=False): Arguments are passed as a list of strings directly to the binary via system calls. No shell is invoked, so metacharacters cannot execute.

Alternative Mitigations from Lecture Slides

1. Avoid the Shell

Directly invoke binaries using system APIs (e.g. execve in POSIX, CreateProcess in Windows) or use native language standard library network modules rather than invoking command-line utilities. Without a shell interpreter, metacharacters have no special meaning.

2. Parameterised Execution with an Argument Vector

Pass command arguments as separate elements of an array/vector (e.g. ["ping", "-c", "1", host]) with shell=False. The OS treats each element as literal data for that parameter, making command chaining syntactically impossible.

3. Allow-List Input Validation

Enforce strict syntactic rules using positive allow-lists rather than denylists. Validate inputs against strict data formats (e.g., regex ^[a-zA-Z0-9.-]+$). Denylists are fragile and easily bypassed with alternative shell syntax like $IFS or quotes.

4. Principle of Least Privilege

Run the web server under an unprivileged system service account (e.g., nobody or www-data) with minimal filesystem and operating system permissions. Restrict access to administrative tools and sensitive system files to limit blast radius.
